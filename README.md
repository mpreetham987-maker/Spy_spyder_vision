# Spy Spider Vision

Premium controller application for a 4-legged spy spider robot. Connects to
the robot over Bluetooth Classic (SPP) for movement/servo control, and
displays a live MJPEG video feed from an onboard ESP32-CAM module over
Wi-Fi. Includes on-device AI object detection running on the real decoded
camera frames.

## Project structure

```
lib/
  core/        constants, theme
  data/        models + services (bluetooth, camera stream, prefs, AI)
  features/    one folder per screen/feature (splash, dashboard, camera,
               manual_control, ai_detection, settings)
  providers/   ChangeNotifier state (robot, camera, settings)
  shared/      reusable widgets used across features
  main.dart
android/       full Gradle Android project
ios/           full Xcode iOS project
assets/        drop app images/icons here (see pubspec.yaml)
test/          widget/unit tests
```

## Requirements

- Flutter SDK 3.19+ (Dart 3.3+) — install via https://docs.flutter.dev/get-started/install
- Android Studio (for Android builds) or Xcode 14+ (for iOS builds, macOS only)
- A physical device is recommended for testing Bluetooth and the camera
  stream — Bluetooth Classic (SPP) is not available on most emulators/simulators.

## Getting started

```bash
flutter pub get
flutter doctor         # confirm your toolchain is set up correctly
flutter devices        # confirm a device/emulator is attached
flutter run
```

## Building an APK

```bash
flutter build apk --release
# output: build/app/outputs/flutter-apk/app-release.apk
```

For a smaller, Play Store-ready bundle:

```bash
flutter build appbundle --release
```

## Building for iOS

```bash
cd ios && pod install && cd ..
flutter build ios --release
```

Opening `ios/Runner.xcworkspace` (not `.xcodeproj`) in Xcode after `pod install`
is the supported way to run/debug on iOS.

## Notes on this scaffold

- **Bundle/application IDs** are currently set to
  `com.spidervision.spy_spider_vision` (Android) and
  `com.spidervision.spySpiderVision` (iOS). Change these in
  `android/app/build.gradle` (`namespace` / `applicationId`) and in Xcode's
  Signing & Capabilities tab (or `PRODUCT_BUNDLE_IDENTIFIER` in
  `project.pbxproj`) before publishing.
- **Android Gradle Plugin is pinned to 7.4.2 / Gradle 7.6.3** rather than the
  newest AGP 8.x line. This is deliberate: `flutter_bluetooth_serial`, one of
  this app's core dependencies, is an unmaintained package that is missing the
  `namespace` declaration AGP 8 requires, which makes it fail to build on
  newer AGP versions. If you later replace that plugin with a maintained
  Bluetooth Classic alternative, you can safely move to a newer AGP/Gradle.
- **`android/gradle/wrapper/gradle-wrapper.jar` (the wrapper's binary
  bootstrap jar) is not included.** This project was generated in a
  network-restricted environment that could not fetch that binary from
  Gradle's servers. Before your first build, do one of the following:
  - Open the project in Android Studio — it detects the missing/incomplete
    wrapper and offers to regenerate it automatically, or
  - Run `gradle wrapper --gradle-version 7.6.3` from the `android/` folder if
    you have any Gradle installed locally, or
  - Run `flutter build apk` from the project root — recent Flutter tooling
    will bootstrap Gradle itself in many cases.
- **`android/local.properties` and `ios/Flutter/Generated.xcconfig`** are
  intentionally not included (they're machine-specific and are normally
  auto-generated by Flutter/Android Studio on first run — see
  `android/local.properties.example` and
  `ios/Flutter/Generated.xcconfig.example` for what they'll contain). They're
  already listed in `.gitignore`.
- **App icons** are placeholder art (a simple gold spider/lens mark on a deep
  indigo background matching the in-app "royal" theme) generated for this
  scaffold — swap `android/app/src/main/res/mipmap-*/ic_launcher.png` and
  `ios/Runner/Assets.xcassets/AppIcon.appiconset/*.png` for your real icon
  before shipping. The [`flutter_launcher_icons`](https://pub.dev/packages/flutter_launcher_icons)
  package automates this from a single source image.
- If anything under `android/` or `ios/` ever looks inconsistent (e.g. after
  a Flutter upgrade), running `flutter create .` from the project root
  safely regenerates platform scaffolding without touching your `lib/` code.

## Permissions this app requests

- **Bluetooth** (scan/connect, plus legacy location permissions Android
  requires for classic Bluetooth discovery pre-Android 12) — to pair with
  and send movement/servo commands to the robot.
- **Internet / network state / Wi-Fi state** — to pull the MJPEG video
  stream and status polling from the ESP32-CAM over your local network.
- **No camera permission is requested** — the app never uses the phone's
  own camera; all video comes from the robot's ESP32-CAM.
